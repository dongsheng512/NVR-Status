### 2.2 已知限制

| 限制 | 影响 | 优先级 |
|------|------|--------|
| 通道表为 ttk.Treeview 嵌在 CTk 中 | 滚动/样式/排序体验一般 | 中 |
| GUI 集中在单文件 `gui_app.py`（~2500 行） | 维护成本高 | 中 |
| 单次巡检选一台设备 | 多 NVR 需多次点击 | 低～中 |
| 安装包未签名 | Mac/Win 首次打开需手动信任 | 中（分发侧） |
| 深度抽检依赖 ffmpeg | 未捆绑则功能降级 | 已文档化 |
| UI 框架为 CTk | 现代皮肤够用；强表格/扩展能力有限 | 见选型 |

## 3. 战略决策：UI 框架

### 3.1 结论（2026-08 分析）

| 决策 | 内容 |
|------|------|
| **默认** | **继续 CustomTkinter**，优先业务与局部体验修复 |
| **若离开 Tk 系** | 选 **PySide6**，不选 wxPython |
| **wxPython** | 技术可行，但对本项目 ROI 偏低（原生感优势用不上、现代 UI 成本高） |
| **迁移触发条件** | 见下表；未满足则不做全量重构 |

### 3.2 迁移触发条件（满足 ≥2 条再立项）

1. 通道表交互（排序/筛选/大量行）成为明确投诉  
2. 规划 6–12 个月内多页（历史报告、多 NVR 队列、插件式扩展）  
3. 有 2–4 周连续投入 + 双平台打包回归资源  
4. 1–2 天 PySide6 POC 通过真机与打包验收  

### 3.3 决策依据摘要

- 业务与 UI 已分离，换壳可行，但 `gui_app` 重写成本不低  
- 现产品是「现代工具感」而非「系统原生设置」→ PySide6 > wx  
- 详细对比：[02](analysis/02-wxpython-eval.md) · [03](analysis/03-wx-vs-pyside6.md) · [04](analysis/04-pyside6-details.md)

## 4. 路线图

### 阶段 A — 稳定交付（当前主线，不换框架）

**目标：** v1.x 可稳定内部分发  

| 序号 | 项 | 说明 | 预估 |
|------|-----|------|------|
| A1 | 部署文档与发布清单 | 本文 + DEPLOYMENT | 已完成 |
| A2 | 双平台构建回归 | 按验收清单打 zip | 0.5–1 天 |
| A3 | 通道表体验小修 | 滚动、列宽、异常筛选（CTk/tksheet） | 1–3 天 |
| A4 | 导出/日志小改进 | 打开导出目录、日志行数上限 | 0.5–1 天 |
| A5 | （可选）代码签名说明 | 文档级；真签名看证书预算 | — |

**退出标准：** 固定测试 NVR 上 Win+Mac 包各一份，验收清单全勾。

---

### 阶段 B — 工程化（仍可在 CTk 下做）

**目标：** 降低维护成本，为可能的 UI 换壳铺路  

| 序号 | 项 | 说明 | 预估 |
|------|-----|------|------|
| B1 | 抽出 `ScanWorker` 与导出逻辑 | 无 UI 依赖，便于单测 | 1–2 天 |
| B2 | 拆分 `gui_app` 模块 | main_window / table / dialogs | 2–4 天 |
| B3 | 进度与取消 | 深扫可中断；进度节流 | 1–2 天 |
| B4 | 崩溃日志 | 打包无 console 时写用户目录 log | 0.5 天 |
| B5 | （可选）GitHub Actions 双矩阵 artifact | 见 DEPLOYMENT §9 | 1–2 天 |

**退出标准：** 业务逻辑可在无 GUI 下测试；GUI 文件单文件不超过「可读」阈值。

---

### 阶段 C — UI 升级评估 / PySide6（条件触发）

**目标：** 仅在 §3.2 触发后执行  

| 序号 | 项 | 说明 | 预估 |
|------|-----|------|------|
| C0 | **Go/No-Go** | 对照触发条件开会确认 | 0.5 天 |
| C1 | POC | 主窗 + Signal + 表 + 真机 quick/deep + 一平台打包 | **1–2 天** |
| C2 | 全量迁移 | 档案/设备/导出/主题对等 | 2–3 周 |
| C3 | Model/View 表 + 筛选排序 | 迁移时一并做 | 含在 C2 或 +2 天 |
| C4 | 双平台打包与回归 | 新 spec、体积、插件路径 | 3–5 天 |
| C5 | 下线 CTk 入口 | 文档与依赖清理 | 0.5 天 |

**POC 失败则：** 停止迁移，回到阶段 A/B。

详见 [04-pyside6-details.md](analysis/04-pyside6-details.md) 迁移顺序与验收。

## 7. 风险登记

| 风险 | 影响 | 缓解 |
|------|------|------|
| 全量换 UI 拖垮业务迭代 | 高 | 触发条件 + 强制 POC |
| PyInstaller + Qt 体积/插件 | 中 | 精简 excludes；双平台早打包 |
| 未签名包被拦截 | 中 | 用户说明 + 可选签名 |
| 真实密码进仓库 | 高 | .gitignore + example 配置 |
| NVR 固件差异导致 ISAPI 字段不同 | 中 | 多机回归；宽松解析 |
| ffmpeg 许可与体积 | 低 | 可选捆绑；文档说明 |

## 8. 成功指标（建议）

| 指标 | 目标 |
|------|------|
| 快速巡检（示例 32 路） | 可接受时间内完成（内部标定基线） |
| 同事首次成功配置 | 文档 + GUI 内无卡死 |
| 严重问题漏报 | 与人工抽查对比可接受 |
| 安装成功率 | 按说明操作可启动 ≥ 目标比例 |
| 崩溃可诊断 | 有日志或明确错误弹窗 |

具体数值由使用场景标定后写入发布说明。

## 10. 近期推荐执行顺序（默认不换框架）

1. 按 [DEPLOYMENT.md](DEPLOYMENT.md) 打一版 Win/Mac 内网包并完成验收  
2. 收集同事对「表格/多设备」的真实反馈  
3. 有余力做 B1（抽出 Worker）— 无论是否上 Qt 都有价值  
4. 仅当表格/扩展成为瓶颈时，启动 C1 POC，再决定是否 v2  

**原则：能用局部改进解决的，不上框架级重构。**
